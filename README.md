# GUVI Refunds Tracker & Dashboard

A full‑stack internal ops tool for tracking and processing refunds for cohort‑based bootcamps.

## Tech stack
- **DB**: PostgreSQL (Neon) – Prisma ORM
- **Backend**: Node.js + Express + TypeScript
- **Frontend**: React + Vite + Tailwind + Recharts (not included here – UI to be built separately)
- **Auth**: JWT + bcrypt, role‑based middleware
- **File storage**: Cloudflare R2 (attachments)
- **Hosting**: Render (backend) / Vercel (frontend)

## Quick start (backend)
```bash
# Clone repo
git clone <repo-url>
cd <repo>

# Install deps
npm install

# Set env vars (example)
cp .env.example .env
# edit .env – set DATABASE_URL, JWT_SECRET, etc.

# Run Prisma migrations & seed
npx prisma migrate dev --name init
npm run seed   # runs prisma/seed.ts

# Start dev server
npm run dev
```

## Frontend

The React dashboard lives in `frontend/` and is built with Vite, Tailwind, TanStack Query, React Router, Recharts, React Hook Form, and Zod.

```bash
cd frontend
npm install
npm run dev
```

Set `VITE_API_URL` when the API is not running at `http://localhost:3000/api`.

The frontend stores the JWT in `localStorage` because the current backend returns a bearer token and does not set an httpOnly cookie. This is a deliberate fallback with a larger XSS exposure; production auth should move to a secure, httpOnly cookie when the backend supports it.

The UI already handles the current auth, summary, refund creation, eligibility, and status-transition contracts. List/detail, trends, BD breakdown, notes, attachments, and admin endpoints are surfaced as explicit per-panel unavailable states until those backend routes are implemented. CSV export is also marked as pending rather than silently exporting an incomplete dataset.
